# SCPA Online NCF Service

This service is an online NeuMF recommender. It keeps trainable cold-start user
and item factors, stable string-ID mappings, and a PyTorch GMF+MLP fusion model
for the served NCF score.

## How It Learns

- Scraped jobs arrive through `POST /jobs/upsert`.
- Job text embeddings initialize item factors.
- New users are cold-started from profile embeddings generated by SBERT.
- Every `view`, `click`, `apply`, or `skip` feedback event runs SGD on an
  implicit-feedback objective.
- Model state is persisted to `weights/online_ncf.json`.
- NeuMF `state_dict` weights are persisted to `weights/online_neumf.pt`.

The model therefore improves while the system is running. Scrape data expands
and refreshes the item universe; feedback provides the preference labels.

## Endpoints

- `GET /health`
- `POST /jobs/upsert`
- `POST /recommend/ncf`
- `POST /predict`
- `POST /feedback`
- `POST /train`
- `GET /model/status`

## Runtime Model

The served score combines cold-start factor features with the NeuMF forward
pass:

```text
score = sigmoid(0.45 * factor_logit + 0.55 * neumf_logit)
neumf_logit = Linear([GMF(user,item), MLP(user,item)])
```

Updates use logistic error for factors and BCEWithLogitsLoss for the NeuMF
branch:

```text
error = target - score
user_factor += lr * (error * item_factor - reg * user_factor)
item_factor += lr * (error * user_factor - reg * item_factor)
neumf_optimizer.step()
```

This is fast enough for request-time scoring and is a real learning algorithm:
the same user/job pair changes score after feedback.

## Latency

Inference is vector dot products over candidate jobs. Heavy SBERT encoding is
done by the SBERT service and cached/upserted by the pipeline.
